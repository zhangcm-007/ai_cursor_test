# 用例模板（case-template）

> 此文件是 testcase-generator skill 在 Step 2 套用的标准模板。
> 生成用例时严格按照此结构输出，字段不可增减。

---

## Markdown 表格模板

| 编号 | 标题 | 测试点 | 用例类型 | 前置条件 | 步骤 | 预期结果 | 实际结果 | 执行状态 | 优先级 |
|------|------|--------|----------|----------|------|----------|----------|----------|--------|
| TC-001 | {动宾结构标题} | {本条验证的核心点} | {功能测试/接口测试/UI测试} | {执行前的环境和数据状态} | 1.{操作步骤1} → 2.{操作步骤2} | 1.{预期结果1} → 2.{预期结果2} | | | {P0/P1/P2/P3} |

---

## 字段填写规范

### 编号
- 格式：`TC-三位序号`，如 `TC-001`、`TC-002`
- 整个文档全局自增，跨子模块、跨模块连续编号，不重置

### 标题
- 动宾结构，直接描述行为，如：`提交有效登录请求`、`拒绝空密码登录`
- 禁止：`测试登录功能`、`验证xxx`

### 用例类型
- 功能测试 / 接口测试 / UI测试 / 性能测试 / 兼容性测试

### 步骤 & 预期结果
- 多步骤使用 ` → ` 分隔，如：`1.输入用户名 → 2.点击登录`
- 步骤与预期结果必须一一对应（数量相同）

### 优先级
- P0：冒烟，阻塞上线
- P1：核心流程，每版必测
- P2：一般场景，按需执行
- P3：边缘场景，时间充裕时执行

## 用例组织结构（三层）

按 **模块 → 子模块 → 用例** 三层组织输出，每个子模块一张独立表格，例如：

```
# 登录模块

## 子模块：密码登录

| 编号 | 标题 | 测试点 | 用例类型 | 前置条件 | 步骤 | 预期结果 | 实际结果 | 执行状态 | 优先级 |
|------|------|--------|----------|----------|------|----------|----------|----------|--------|
| TC-001 | 提交有效密码登录 | 正向主流程 | 功能测试 | 用户已注册 | 1.输入正确邮箱和密码 → 2.点击登录 | 1.- → 2.跳转首页 | | | P0 |
| TC-002 | 拒绝错误密码登录 | 密码校验 | 功能测试 | 用户已注册 | 1.输入正确邮箱+错误密码 → 2.点击登录 | 1.- → 2.提示"密码错误" | | | P0 |

## 子模块：验证码登录

| 编号 | 标题 | 测试点 | 用例类型 | 前置条件 | 步骤 | 预期结果 | 实际结果 | 执行状态 | 优先级 |
|------|------|--------|----------|----------|------|----------|----------|----------|--------|
| TC-003 | 发送验证码成功 | 验证码发送 | 功能测试 | 邮箱已注册，网络正常 | 1.输入邮箱 → 2.点击发送验证码 | 1.- → 2.提示"验证码已发送"，按钮进入60s倒计时 | | | P0 |
```

### 编号命名规则

格式：`TC-三位序号`，全局自增，示例：

| 编号 | 所属模块 | 所属子模块 |
|------|----------|------------|
| TC-001 | 登录模块 | 密码登录 |
| TC-002 | 登录模块 | 密码登录 |
| TC-003 | 登录模块 | 验证码登录 |
| TC-004 | 注册模块 | 邮箱注册 |
