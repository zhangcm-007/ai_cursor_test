# 需求文档生成

## 角色定位

以**测试工程师**视角整理需求：内容描述清晰、字段规范完整、冲突处有标注；**完整吸收产品 PRD 中的验收标准与测试用例（场景 + 期望值）**，让测试人员读完即可设计/对齐测试用例。

## 生成步骤

### Step 1：读取文档

读取用户提供的所有文档：
- **子 PRD**（具体功能需求，**冲突时以此为准**）
- **父 PRD**（通用规则、输入边界、异常分支）
- **后端接口文档**（字段类型、必填性、响应结构）
- **前端开发规范**（组件类型、校验规则、交互细节、本期隐藏功能）

### Step 1.5：提取 PRD 内嵌测试用例与验收标准（强制执行）

产品 PRD 常在文末或独立章节提供 **「验收标准」「测试用例」「验收场景」** 等，格式多为表格：**步骤 / 操作 / 预期结果**，或直接列出场景与期望值。**必须全文检索并提取**，不可只读功能描述而忽略测试章节。

**检索关键词（中英文）**：
`验收标准`、`验收`、`测试用例`、`测试场景`、`Test Case`、`Acceptance`、`步骤`、`预期结果`、`期望结果`、`Given`、`When`、`Then`

**提取规则**：
| 规则 | 说明 |
|------|------|
| **保留原文** | 操作步骤、输入数据、期望结果尽量**原文摘录**，不改写提示语与示例值 |
| **结构化入库** | 每条场景记录：来源文档 + 章节号、场景编号/步骤号、前置/操作、期望结果 |
| **并入正文** | 能对应到字段/流程/异常的需求条目，在 §3～§6 **正文内引用或复述**该期望（标注 `〔PRD §x.x〕`） |
| **独立成章** | 无法在正文拆分的完整流程/端到端场景，写入 **§9 PRD 验收与测试场景** |
| **与规范对齐** | PRD 测试用例中的具体数据（如 `buffett-audit`、disabled、Toast 文案）视为产品**已定义期望**，写入需求文档，不作为「待澄清」 |
| **冲突处理** | PRD 测试期望与接口文档/前端规范冲突时：需求正文**以子 PRD 为准**，在 §9 或字段表标注 `⚠️ 与 [文档名] 冲突`；澄清文档由澄清 skill 单独列出 |

**PRD 有、其他文档无**：以 PRD 测试用例/验收为准补全需求（例如按钮 disabled 条件、预览步骤、列表展示）。

**其他文档有、PRD 测试未覆盖**：仍写入需求正文，在 §9 标注 `待 PRD 补验收场景` 或交由澄清文档跟踪。

### Step 2：整理字段规范

对每个字段按以下维度整理，**有明确定义的直接写入，有冲突的按子PRD为准并标注`[以子PRD为准]`，完全缺失的标注`[待澄清]`**：

- 是否必填
- 组件类型（Input / TextArea / Checkbox / Select 等）
- 字符类型（是否有格式限制，如 kebab-case）
- 长度限制（上下限）
- **边界展示（有长度限制时）**：最短/最长合法值在**表单、预览、列表、详情**等页面的完整展示要求（若 PRD 测试用例已描述，照抄并标注来源）
- 超出处理方式（阻断 / 软提示）
- 校验时机（实时 / 失焦 / 提交时）
- 报错提示文案
- 本期是否实现

### Step 3：整理流程与按钮逻辑

- 入口与触发方式
- 完整提交流程（从点击到落盘）
- 按钮 disabled 条件（**优先采用 PRD 测试用例中的描述**）
- 取消/关闭行为

### Step 4：整理异常分支

从以下来源合并，**去重但保留 PRD 测试用例中的具体期望表述**：
- 父 PRD 逆向流程总表
- 子 PRD 异常分支
- **PRD §测试用例 — 异常分支** 表格

### Step 5：生成文档

输出路径（默认）：`{工作区根}/test/requirements/test_[功能名]-requirements.md`。若 `test/requirements/` 不存在则先创建。用户明确指定其他路径时从其指定。

## 输出规范

- 文件名以 `test_` 开头
- **必须包含 §9**（若 PRD 无任何测试/验收章节，§9 写「PRD 未提供内嵌测试用例，以下场景来自功能描述整理」并列出从正文推导的场景）
- 有冲突的字段标注来源和 `[以子PRD为准]`
- 待澄清的字段标注 `[待澄清]`；**PRD 测试用例已写明的期望不得标为待澄清**
- 本期隐藏的字段仍写入文档，标注 `❌ 本期隐藏`
- 引用文案时保留原文，不改动提示语
- 生成后提示测试同学：§9 可直接映射为测试用例 TC 或作为用例步骤/预期的溯源
